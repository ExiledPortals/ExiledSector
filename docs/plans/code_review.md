# Code review 2026-10-23: plan

Status: review done; skill tree bugs 1-16 and hull upgrades bugs 17-18 and Star Charts bugs 20-23 and core bug 24 fixed on parallel-work, 19 not needed, the rest open. Seven read-only reviewers covered one module each (skill tree split into logic and UI) plus one for cross-module duplication. Each finding was re-read by its reviewer; CONFIRMED means the code was re-checked and the failure follows, PLAUSIBLE means it depends on engine behaviour or data that wasn't verified. Findings marked (checked) were also re-checked in the main session.

Paths are relative to each module's `src/main/java/exiledsector/` (or `exiledlib/` for Exiled Lib) unless given in full.

## Bugs

Most severe first within each module.

### Skill tree

1. FIXED (parallel-work): the migration marks only gates whose boss is beaten. CONFIRMED (checked). `effects/GateRewardAnchors.markOpenGatesGrantedOnce` marks a reward gate granted when `isLocked(conditions, null)` is false. That is also true when the gate's mod is missing (`ModGate.isOpen` returns true without the mod) and when the ignore-unlocks override is on, and the migration runs on new games too. A player who starts without Nightcross or RAT and adds it later never gets the Lunar Fleet or Singularity reward anchor. Fix: mark only gates whose boss is already beaten.
2. FIXED (parallel-work): `grantMissed` checks the tree switch. CONFIRMED. `GateRewardAnchors.grantMissed` has no `SkillTreeSetting.enabled()` check (`HyperNavBeaconGrant` has one), and its listener is registered for every domain. With the tree off, beating either boss still drops an anchor and burns the once-per-save grant.
3. CONFIRMED. Renamed nodes aren't migrated for templates: `skills/template/TemplateStepRules` uses `SkillTree.get(step.nodeId())` and `persistence/SkillTreeTemplateStore` compares the raw root id, neither through `NodeReplacements`. A template step on one of the 17 renamed nodes becomes `UNKNOWN_NODE` and auto-allocate stops there. `skills/npc/NpcTreeTag` resolves its root entry without `NodeReplacements.resolve` too (latent).
4. FIXED (parallel-work): a malformed gate is logged and skipped. CONFIRMED. `skills/unlock/NodeGates.register` throws on the first malformed gate and `load` then sets an empty map, which opens every gated area. Skip the bad gate instead (or fail closed).
5. CONFIRMED (console only). `console/LockAreasCommand.relockOpenAreas` relocks `threatFought`, `nightcrossLunarFleetDefeated` and `nightcrossAncientPrototypeFound`, but nothing calls `RelockedGates.reopen` for them, so they stay locked for the save despite the message saying they reopen.
6. FIXED (parallel-work): layout sections skip bad entries one at a time. CONFIRMED, low. `skills/loader/SkillTreeLoader` parses each layout section (ring belts, stars, connector curves...) in one try, so one bad entry drops the whole section. Nodes are tolerant per entry.
7. FIXED (parallel-work), partly. Measured on the real tree: 30 ships at 35 nodes took about 92 ms warm (110+ ms cold). The time was not `state()` (about 4%) but `NodeEligibility.check` scanning every allocated node for type conflicts on every candidate in every search. `AllocationGate` now memoises the conflict per candidate type pair, options are a set lookup and `getExclusiveHullModIds` is built once; the same fleet now takes about 64 ms. The rest is one full-tree search per goal; cutting that further means a budget-bounded or incremental search, which changes which tree a seed rolls. Originally: PLAUSIBLE, not measured. NPC tree building: every goal in `NpcSkillTreeBuilder` runs a fresh `search()` that rebuilds `state()` and a new `AllocationGate`, each path step builds another state, and `SkillType.getExclusiveHullModIds()` allocates a new list per call. It runs synchronously on fleet inflation; 20-30 ship fleets at caps 25-35 may hitch. Fix: precompute exclusive sets per `SkillType` at load, reuse `State` within `allocatePath`.
8. FIXED (parallel-work): the label is counted only when the tree opens and after a disassembly, never per frame. PLAUSIBLE, low. `ui/SocketPlacement.refreshButtonLabel` returns early when the total owned item count is unchanged, so removing one subroutine and adding another item in the same frame leaves "Subroutines (N)" stale.
9. FIXED (parallel-work): the encounter dialog showing the window is remembered until it is dismissed. PLAUSIBLE, low. `ui/inspect/NpcTreeInspectInput` only checks the dialog plugin isn't `NpcFleetInspectPlugin`; pressing the key again while its custom visual is open may open it twice.

## Structure

- `SkillEffect` carries skill tree allocation hooks (`blockAllocationReason(ShipFacts, ...)`, `deallocationWarning`, `appliesToNpcShips`) and extends the item framework's `ModifierEffect`. Lower priority; a core registry could hold the allocation rules.
- Exiled Lib hard-codes its host: 7 `"[ExiledSector]"` log prefixes and 117 `"exiledSector_"` key literals in 52 lib files although `HostMod.dataKey` exists (`AffinitySteps` uses `exiledLib_`). Check saves and `skill_types.json` before renaming any key.
- `ui/decoration/RefitShipPortrait`, `InspectedShip` and `ui/RefitBackdrop` in core are used only by hull upgrades and belong there.
- 16 of the 19 chart test files in `exiledsector-mod` import nothing outside core, lib and star charts and may belong in `exiledsector-star-charts`; confirm they don't need the other domains installed.
